Login e sessão

A entrada é por telefone e senha. Numa instalação nova, o responsável cria o administrador antes do primeiro login.

Versão de avaliação. Este manual descreve a aplicação web 2.1 usada no ponto de retirada. A pré-release Windows v2.1.0-rc1.2 está publicada para avaliação, sem assinatura digital, com instalador e ZIP. Não há SaaS público. O produto é Free; o suporte opcional é pago à parte. O GA do instalador com SQLite continua em 06 de abril de 2027. Conectores vivos no código: Mercado Livre, Shopee e Temu.

Tela de autenticação

  • Campo Telefone, com máscara +55 (DD) 9XXXX-XXXX
  • Campo Senha, com botão para mostrar ou ocultar
  • Botão Entrar e a caixa Lembrar-me (nesta versão ela não prolonga a sessão)
  • Link Recuperar com código offline
  • Rodapé com Primeiro acesso? Configure o administrador desta instalação

Procedimento

  1. Digite o telefone cadastrado, com DDD
  2. Digite a senha
  3. Clique em Entrar
  4. Aguarde o redirecionamento para o dashboard

A conta é identificada pelo telefone: o Hub não aceita e-mail como login. Se a senha for recusada, a tela mostra credenciais inválidas — confira o telefone antes de tentar de novo.

Recuperação de senha — código offline

A recuperação de senha não usa SMS, e-mail nem mensagem instantânea: ela depende dos códigos gerados ao criar a conta ou no perfil. Os avisos de WhatsApp/Telegram tratam de pedido, não de senha.

  1. Na tela de login, clique em Recuperar com código offline
  2. Informe o telefone cadastrado
  3. Informe um dos códigos guardados
  4. Defina a nova senha e confirme (mínimo de 12 caracteres)
  5. Entre de novo, com o telefone e a nova senha

Cada código serve uma vez; ao redefinir a senha, os demais códigos do conjunto são invalidados. Sem um código válido não há recuperação automática — nesse caso, outro ADMIN redefine a senha em Administração → Usuários (ação Resetar senha) e informa a senha temporária mostrada na tela. Guarde os códigos fora do computador do ponto.

Sessão, perfil e saída

  • A sessão começa quando você entra; o cookie dura enquanto o navegador estiver aberto
  • A sessão expira após 30 minutos de inatividade — é o padrão do Tomcat, porque o aplicativo não define prazo próprio; ao fim do turno, clique em Sair
  • Fechar o navegador encerra o cookie de sessão
  • Perfil: dados pessoais, troca de senha e geração dos códigos de recuperação
  • Logout: use Sair no menu superior
